# NVFP4 W4A16 on RX 9070 XT

Tested on 2026-10-19 with the miner running. Both BF16 and FP16 activations
work with packed NVFP4-style weights decoded into the matching 16-bit WMMA
input type. All 36 correctness cases passed across six kernel variants, and
every measured output agreed numerically with the same-run predecoded baseline.
These standalone experiments change no production source or defaults.

## Representation and kernels

All 2032 combinations of E2M1 codes and nonnegative finite E4M3 local scales
are exactly representable in both BF16 and FP16, verified exhaustively on the
host. GPU expansion is checked against host expansion for every input weight.
The weight global FP32 scale is applied after accumulation (0.75 in varying-scale
tests, 1 in the unit-scale case). Signed zero is compared numerically.
Activations retain their full 7-bit BF16 or 10-bit FP16 mantissas; they are not
FP4-derived. A direct FP8/INT8 conversion would lose information for these
activations, so this W4A16 suite uses BF16/F16 WMMA with FP32 accumulation.

`simple` uses a one-wave 16x16 tile. `tile16` uses a 16x64 tile, and `tile64`
uses a 64x64 tile; both tiled kernels use four waves and K32 LDS panels.
Each topology has packed and predecoded variants. Packed kernels decode weights
while loading; predecoded kernels read 16-bit weights. The latter need four
times the weight payload of packed nibbles, excluding local-scale storage.
Weight expansion is timed separately as `expand_weights`, outside GEMM timing.

A is row-major `[M,K]`, weights are `[N,K]`, and output is FP32 `[M,N]`.
Weights use low-nibble-first E2M1 and linear `[N,K/16]` E4M3 scales, not NVIDIA's
swizzled storage layout. K is zero padded to a multiple of 64. Quantization,
model loading, and NVIDIA storage interoperability are outside this test.

## Measurements

RX 9070 XT (gfx1201), HIP 7.16 / clang 24, `-O3`, Linux; Threadripper 1950X,
128 GiB installed RAM (RAM speed unmeasured). GPU use was 100% at both snapshots,
core clocks 1897/1909 MHz, memory clock 875 MHz, package power 209/213 W,
and junction temperature 86 C. Miner settings were unchanged.

Five warmups per GEMM mode, five rounds of 20 launches, rotating mode order.
HIP events include possible CPU submission gaps. Buffers remain resident and
are reused without cache eviction. Allocation, transfers, and validation are
excluded. This is a warm synthetic GEMM comparison, not streamed expert inference.

Times below are median milliseconds with minimum–maximum across five rounds.
The two 64x64 variants have matching topology; the simple predecoded column
shows that a different tile can be faster. Miner interference is large, so
small differences do not establish a ranking.

| Activation | M×N×K | Packed 64x64 | Predecoded 64x64 | Predecoded 16x16 |
|---|---|---:|---:|---:|
| BF16 | 512×2048×4096 | 1.135 (1.127–1.303) | 1.113 (0.943–1.163) | 0.926 (0.905–1.491) |
| BF16 | 512×4096×2048 | 0.795 (0.781–1.516) | 0.726 (0.695–1.241) | 1.298 (1.097–2.144) |
| BF16 | 1024×1024×1024 | 0.264 (0.257–0.579) | 0.248 (0.242–0.599) | 0.226 (0.217–0.260) |
| FP16 | 512×2048×4096 | 1.158 (1.104–1.280) | 1.023 (0.963–1.189) | 0.916 (0.869–1.507) |
| FP16 | 512×4096×2048 | 0.796 (0.775–1.535) | 0.708 (0.693–1.451) | 1.365 (1.089–2.098) |
| FP16 | 1024×1024×1024 | 0.264 (0.259–0.578) | 0.244 (0.237–0.600) | 0.224 (0.221–1.254) |

For M=1,16,64, the simple packed kernel usually had the lowest packed median.
All shapes and expansion timings are in the CSV; M=1 is not a specialized GEMV
implementation. The 16x64 LDS tile did not show a consistent benefit in this run.
For M=512, the packed 64x64 path reached about 7.4–10.8 logical TOPS, with no
activation quantization. This supports further tuning of fused 16-bit decoding;
it does not establish a speedup over a tuned GEMM/GEMV library.

## Validation and reproduction

The 36 small cases cover codebooks, all finite scale codes, basis vectors,
cancellation, zeros, normal activation exponent ranges, odd dimensions, K tails,
and multiple output tiles. Every output is compared with a scalar GPU FP64
reference and an FP32 summation-error bound. The scalar reference is independently
checked on the CPU for all small-case outputs and 64 outputs per benchmark shape.
Every GEMM output is checked again after each timed round, with trailing output
canaries. All six modes must also equal the predecoded baseline numerically.
Activation NaNs/Infs and exhaustive activation subnormals were not tested.

The build passed without warnings. Compiler-generated assembly contains both
BF16 and FP16 WMMA instructions. No GPU memory sanitizer, model-quality test,
end-to-end inference, idle-GPU run, or tuned library comparison was performed.
Only standalone HIP sources were added; CUDA/SYCL backends were not changed or built.

```sh
make -C experiment/nvfp4_rdna4 -f Makefile.w4a16 -j2 all
make -C experiment/nvfp4_rdna4 -f Makefile.w4a16 test isa
make -C experiment/nvfp4_rdna4 -f Makefile.w4a16 bench
```
